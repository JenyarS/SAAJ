# UKH Connect – Coding Standard

## Code (Product Standard)


- We follow PEP 8 for Java code.
- Functions and methods use descriptive verbs, while classes use nouns.
- Class names use camelCase (e.g., `studyGroup`).
- Function and variable names use snake_case (e.g., `join_group`).
- Constants are written in UPPERCASE (e.g., `MAX_CAPACITY`).
- Every class and public function must have a docstring explaining its purpose.
- Avoid magic numbers; use named constants instead.
- Do not nest `if` statements more than two levels deep.


## Git (Process Standard)


- Never commit directly to the `main` branch.
- Create one branch per feature using `feature/<short-name>`.
- Use meaningful branch names, such as `feature/study-group`.
- Commit messages must begin with a verb: Add, Fix, Update, or Remove.
- Make small, frequent commits with clear messages.
- Merge changes into `main` only through a reviewed pull request.
